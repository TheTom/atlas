# Native FP8 FFN kernel selection

Commit `ce4f8af751d080dc37912b7c522857e01923128d`, based on `b3025ab`. The native FP8 FFN previously used the base 64×64 tiled GEMM for both short batches and full prefills, despite having compatible kernels in the existing bundle. The first native H100 ladder showed a large C16 decode penalty; that observation motivates this dispatch fix, but does not establish its eventual speedup.

The revised production path uses existing `w8a16_gemv_batch4` for one through four rows when present, then the existing transposed preference, then `w8a16_gemm_pipelined`, then the original base GEMM. The actual loader has no transposed FP8 copies today. All branches retain the same original E4M3 weight bytes, FP32 block scales and BF16 input/output. There is no W8A8 activation conversion, new weight allocation, or kernel change. Default NVFP4 and C1 `forward()` decode are untouched.

Source contracts: `layers/ops/fp8_gemv_batch.rs` documents the M≤4 block-scaled batch GEMV; `kernels/gb10/common/w8a16_gemv_batch4.cu` shares each decoded weight among the actual rows, with the same per-row reduction as C1 GEMV. This reduction differs from a tensor-core GEMM, so do not claim bit identity with the previous batched GEMM. `layers/ops/gemm_quant.rs` and `common/w8a16_gemm_pipelined.cu` retain BF16-expanded unscaled E4M3, two-level FP32 accumulation and an FP32 scale fold at each 128-K block. The pipelined 128×32 tile uses 256 threads; base uses 64×64 and 128 threads. The existing ~4.6× comment refers to GB10, not an H100 measurement.
